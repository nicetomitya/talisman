# Талисман — прототип P0

Единая страховая платформа: кабинеты клиента, агентства и платформы (администратор, представитель страховщика, поддержка), reverse auction по классическим продуктам (КАСКО, квартира/дом) и событийные продукты RAIN01 и WIND01.

> **Это демонстрационный прототип.** Все внешние системы (страховщики, платежи, погода, подпись, ИИ, антивирус, почта) — эмуляторы. Реальные деньги не списываются, полисы не выпускаются. Каждый страховой документ помечен «Демонстрационный документ. Не является действующим страховым полисом». Все люди, компании и контакты вымышлены (домен `.test`).

Документы проекта: ТЗ — [`docs/TZ_original.txt`](docs/TZ_original.txt), рабочая выжимка и архитектура — [`PROJECT_SPEC.md`](PROJECT_SPEC.md), статус и отчёт по критериям приёмки — [`IMPLEMENTATION_STATUS.md`](IMPLEMENTATION_STATUS.md), решения и ограничения — [`docs/DECISIONS.md`](docs/DECISIONS.md), API — [`docs/API.md`](docs/API.md), блокеры P1 — [`docs/P1_BLOCKERS.md`](docs/P1_BLOCKERS.md).

## Запуск с чистой базы

Нужны Node.js 22 и PostgreSQL 16. Платные ключи не нужны.

```bash
docker compose up -d db          # или свой PostgreSQL 16 с БД talisman и talisman_test
npm install
cp .env.example .env
npm run reset-demo               # миграции + демо-данные (повторяемо: каждый запуск очищает данные и заполняет заново)
npm run dev                      # приложение: http://localhost:3000
npm run worker                   # в отдельном терминале: фоновые задачи (дедлайны торгов, вебхуки, проверки событий, повторы)
```

Без worker приложение работает, но дедлайны, обработка вебхуков и проверки событий выполняются только кнопкой «Выполнить задания сейчас» в демопанели.

## Демосценарии

* **А. КАСКО:** клиент загружает `fixtures/docs/sts_kia_k5.pdf` и `dkp_kia_k5.pdf`, подставляет распознанные поля, подтверждает ключевые, публикует. Агентства отвечают (вручную или автоответом), клиент сравнивает группы сопоставимости, выбирает, знакомится с документами, подписывает кодом из демопочты, платит в эмуляторе, получает полис и чат.
* **Б. RAIN01 / В. WIND01:** демопанель → «Набор для RAIN01» или «Набор для WIND01» (`r52`, `r50`, `r49`, `r_gap_backup`, `r_gap_both`, `w_met`, `w_exact3`, `w_missing`, `w_conflict`), затем «Рассчитать событие сейчас» по полису. Демочасы позволяют перейти к окну события.
* **Г. Агентство:** калькулятор, правила автоответа, продукты, рейтинг, начисления, подписка (оплата счёта, отмена автопродления).
* **Д. Сбои:** режимы эмулятора страховщика («Окончательная котировка»: `unavailable`, `price_changed`; «Подтверждение заключения»: `delay`, `error`), платёж «Успех, но уведомление потеряно» → сверка, «Неизвестный результат».
* Вредоносная инструкция в документе: `fixtures/docs/sts_injection.pdf`. Фильтр загрузок: `fake.pdf`, `active_content.pdf`.

## Режимы

`APP_MODE=demo` — эмуляторы, демопанель, переключение ролей, фиктивная подпись и демовыплаты. `APP_MODE=production` — всё перечисленное отключено; без подключённых адаптеров и записи о запуске любая операция с внешней системой возвращает `INTEGRATION_NOT_CONFIGURED`. Боевой режим в P0 не предназначен для использования: реальных адаптеров нет.
