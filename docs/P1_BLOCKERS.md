# Блокеры перехода к P1

P0 — работающий прототип на эмуляторах. Ни одна реальная операция не включена. До P1 нужно решение владельца и внешние договорённости по каждому пункту ниже.

## Решения владельца

1. Правовая модель платформы и лицензирование (см. U01 в `DECISIONS.md`).
2. Первая пара «страховщик + продукт» для пилота и канал продаж.
3. Включать ли публикацию лучшей цены агентам (U11).
4. Тарифы подписки и доли вознаграждения (U02).
5. Публичное размещение: домен, хостинг в РФ, юридические тексты.

## Внешние интеграции

| Адаптер | Что нужно |
|---|---|
| CarrierAdapter | API или договорённость о тестовом контуре страховщика, ключи |
| PaymentAdapter | Платёжный партнёр страховщика (премии) и отдельный провайдер подписок с 54-ФЗ |
| SignatureAdapter | Провайдер допустимой электронной подписи |
| WeatherAdapter | Договор с поставщиком погодных данных, методика расчёта |
| DocumentAdapter | Утверждённые шаблоны полисов и правил, архив |
| MessagingAdapter | Email/SMS-провайдер, согласованные тексты согласий |
| AIAdapter | Разрешённый провайдер с локализацией данных |
| Antivirus | Сервис проверки файлов |

Ключи запрашиваются только когда соответствующий адаптер готов. Каждый реальный запуск дополнительно требует записи `LaunchApproval` на сочетание страна / страховщик / продукт / канал / платёжный сценарий / версия документов.

## Эксплуатация

* Отдельные секреты (`APP_SECRET`, секреты вебхуков), HTTPS, резервное копирование БД.
* Мониторинг очереди заданий и очереди исключений, оповещения.
* Нагрузочное тестирование торгов и вебхуков.
* Внешний аудит безопасности и тест на проникновение.
* Полный аудит доступности (сейчас — базовые меры, без проверки скринридерами).
