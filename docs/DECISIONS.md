# Журнал решений и неопределённостей

Рутинные решения приняты самостоятельно в рамках ТЗ. Пункты, затрагивающие право, деньги, документы и данные, — **ограничения P0, которые нужно снять до P1**, а не молчаливые допущения.

## Архитектура

| # | Решение | Почему |
|---|---|---|
| D01 | Модульный монолит: Next.js 15 (страницы + API) и отдельный процесс worker на одной БД | Минимум движущихся частей для P0, границы модулей сохранены в `src/server/domain/*` |
| D02 | Очередь заданий в PostgreSQL (`Job`, `FOR UPDATE SKIP LOCKED`), outbox и inbox вебхуков | Задания, дедлайны и идемпотентность переживают рестарт (AC07, AC33) без отдельного брокера |
| D03 | Демочасы — смещение в таблице `Setting`, общее для сервера и worker | Можно «перемотать» к окну события, не трогая системное время |
| D04 | Собственные сессии в БД, Argon2id, TOTP для сотрудников, CSRF double-submit + проверка Origin | Без внешних провайдеров авторизации и ключей |
| D05 | Обновление интерфейса опросом (4 с), а не WebSocket | Проще, сервер всегда отдаёт актуальный снимок; таймер торгов считается по серверному времени |
| D06 | Адаптеры за реестром: в demo — эмуляторы, в production — заглушка, бросающая `INTEGRATION_NOT_CONFIGURED` | Демо-ответ не может «утечь» в боевой режим (AC34) |
| D07 | Деньги — целые копейки, проценты — базисные пункты, погода — целые сотые | Без плавающей точки, детерминированные расчёты |
| D08 | Инварианты дублируются в БД: частичные UNIQUE-индексы (одна активная версия предложения, один резерв), CHECK на лимит выплат | Защита от гонок, а не только от ошибок кода |
| D10 | Выбор предложения — «матч»: торги закрываются, остальные предложения истекают, их агентства получают нейтральное уведомление и теряют доступ к заявке; чат и данные клиента — только у выбранного агентства. Отменить матч можно до оплаты, после этого заявка закрыта, клиент создаёт новую — всем или напрямую тому же агентству | Решение владельца от 02.11.2026: понятная модель «как матч», без возврата к прежним предложениям |
| D11 | Сроки и фиксированные условия: подбор 24 ч; улучшение в последние 15 мин продлевает на 15 мин, всего ≤ 1 ч; после матча 2 ч на ознакомление, подпись и оплату (напоминания за 60 и 15 мин), иначе матч завершается. После подачи агентство может только снизить цену при тех же условиях; отозванное предложение повторно не подаётся. Контакты сторон скрыты, в чате телефоны, почта, ссылки и ники заменяются пометкой. ИИ-помощник (эмулятор) подсказывает клиенту полноту заявки и даёт агентству разбор с коридором цены по тарифу, ничего не меняя сам | Решение владельца от 03.11.2026: без торга после подачи, общение только через платформу |
| D09 | Название механизма в коде — reverse auction; в интерфейсе — «предложения», «улучшение», без «ставок» и обратных отсчётов, давящих на клиента | Требование ТЗ |

## Ограничения P0 (неопределённости)

| # | Вопрос | Как сделано в P0 | Что нужно для P1 |
|---|---|---|---|
| U01 | Правовой статус платформы (агент, брокер, маркетплейс) и кто является стороной договора | Платформа — сервис для агентств; премия идёт клиент → страховщик (эмулятор), платформа деньги клиентов не держит | Юридическое заключение, лицензии, договоры со страховщиками и агентствами |
| U02 | Ставка вознаграждения и доли | Условные 15 % премии, 20 % платформе / 80 % агентству; сторно полное в первые 14 дней, далее пропорционально | Реальные агентские договоры |
| U03 | Тарифы и правила страхования | Демонстрационная тарифная сетка и шаблоны правил с водяным знаком | Утверждённые тарифы и правила страховщика |
| U04 | Электронная подпись | Код из демопочты + журнал доказательств; работает только в demo | Допустимый вид подписи по 63-ФЗ, согласованный со страховщиком |
| U05 | Погодные данные для событийных продуктов | Фиксированные наборы наблюдений, основной и резервный источник | Договор с поставщиком данных, методика, архив |
| U06 | Персональные данные (152-ФЗ), локализация | Только вымышленные данные `.test`; хранение локально | Оценка, уведомление РКН, локализация, политика обработки |
| U07 | Маркетинговые рассылки (38-ФЗ), cookie | Согласия реально управляют отправкой и аналитикой; почта — внутренняя демопочта | Провайдер рассылок, тексты согласий от юриста |
| U08 | Чеки 54-ФЗ для подписок платформы | Счёт и оплата в эмуляторе, чек не формируется | Платёжный провайдер с фискализацией |
| U09 | ИИ-помощник | Детерминированный эмулятор: отвечает только цитатой существующего пункта, иначе передаёт человеку | Выбор провайдера, контроль данных, оценка качества |
| U10 | Антивирус | Демо-проверка (EICAR) в worker | Реальный сервис проверки файлов |
| U11 | Публикация лучшей цены агентам | Выключено: агент видит только своё место и факт наличия лучшего предложения | Решение владельца с учётом конкурентного права |

## Решения по ходу реализации

* TypeScript закреплён на 5.9.3: TypeScript 7 ломает загрузку `next.config.ts`.
* `reset-demo` = `prisma migrate deploy` + сид; сид сам очищает данные (TRUNCATE) и заполняет их через доменные операции, поэтому результат воспроизводим.
* Серверные компоненты не передают функции в клиентские; переходы после действий задаются шаблонами вида `/c/claims/{claimId}`.
* Наблюдения погоды общие для станции и окна, поэтому в тестах каждый случай использует свою дату события.
