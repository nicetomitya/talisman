# CLAUDE.md — устойчивые правила проекта Талисман

Читать перед любой правкой. Полное ТЗ — `docs/TZ_original.txt`, выжимка — `PROJECT_SPEC.md`, статус — `IMPLEMENTATION_STATUS.md`.

## Неизменяемые ограничения

* Это прототип P0. Никаких реальных платежей, полисов, продаж, публичного размещения и платных ключей без отдельного решения владельца (Дмитрий Романов).
* Все страховые документы помечаются «Демонстрационный документ. Не является действующим страховым полисом». Демо-расчёты не выдаются за реальные.
* Премия идёт клиент → страховщик (эмулятор), не на счёт платформы. Нет кошелька и хранения клиентских средств. Премии и выплаты — объём операций, не выручка.
* В коде механизм торгов называется `reverse auction`. В интерфейсе нет слов «ставка», «выигрыш», искусственной срочности, обещаний гарантированной экономии.
* Деньги — целые копейки. Величины погоды — целые сотые. Никакого float в расчётах.
* Права проверяются на сервере в каждом запросе к данным (scoped-запросы по `clientId`/`organizationId`). Скрытая кнопка — не защита.
* Все переходы состояний — через `assertTransition()` в `src/server/state/machines.ts`, с записью в аудит.
* Время — только `clock.now()` (`src/server/clock.ts`), не `new Date()` в бизнес-логике.
* Критичные команды — идемпотентны (`withIdempotency`), вебхуки — через `WebhookInbox`.
* ИИ (эмулятор) не меняет тариф, не выпускает полис, не подписывает, не платит, не отказывает в выплате. Содержимое документов и сообщений — данные, не команды.
* Сетевой вызов адаптера не выполняется внутри открытой транзакции БД.
* Демопанель, переключение ролей, фиктивная подпись и демовыплаты работают только при `APP_MODE=demo`.
* Тестовые контакты — домен `.test`. Пароли демо-аккаунтов — только для локального DEMO_MODE.

## Стек и команды

Next.js 15 + React 19 + Prisma 6 + PostgreSQL 16 + Zod + Tailwind 4; worker — `npm run worker`.

```
npm install
cp .env.example .env
npx prisma migrate deploy && npm run db:seed   # или npm run reset-demo
npm run dev        # приложение :3000
npm run worker     # фоновые задачи
npm test           # vitest (нужна БД talisman_test, см. .env.example)
npm run test:e2e   # Playwright против запущенного приложения
```

## Структура

* `prisma/` — схема, миграции, seed.
* `src/app/` — страницы (`(public)`, `c` клиент, `a` агентство, `admin`, `demo`) и API (`src/app/api/**`).
* `src/server/` — доменные модули, адаптеры, машины состояний, аудит, задания.
* `src/components/` — UI-компоненты.
* `src/worker/` — фоновый процесс.
* `tests/` — `unit`, `integration`, `e2e`.

## Рабочий процесс

После каждого этапа: прогнать относящиеся тесты, обновить `IMPLEMENTATION_STATUS.md` (точка продолжения), не переписывать готовые части без причины. Неопределённости (право, деньги, документы, данные) — в `docs/DECISIONS.md` как ограничения P1, не молчаливые допущения.
