# Талисман — спецификация прототипа P0

Полный исходный текст ТЗ: [`docs/TZ_original.txt`](docs/TZ_original.txt) (версия 1.0 от 2.11.2026). Этот файл — рабочая выжимка: решения, архитектура, модель данных и порядок работ. При расхождении приоритет у исходного ТЗ.

## 1. Что строим

Единая страховая платформа (пилот — Россия, RUB, русский язык) с тремя кабинетами:

* **Клиент** — заявки, сравнение предложений (reverse auction), оформление, полисы, обращения за выплатой, чат, документы, платежи, уведомления, согласия.
* **Агентство** — лента заявок, калькулятор, предложения и улучшения, автоматизация (ручной / с подтверждением / автоматический), клиенты и сделки, продукты и промо, рейтинг, начисления, подписка, команда.
* **Администратор / представитель страховщика / поддержка** — проверка участников, полномочия, каталог и тарифы, торги, очередь исключений, мониторинг событий, обращения, сверка платежей, комиссии и подписки, документы и согласия, аудит, интеграции, аварийная приостановка продаж, двойное подтверждение.

Продукты P0: классические **КАСКО** и **страхование квартиры/дома**; событийные **RAIN01** (дождь на мероприятии) и **WIND01** (недостаток ветра на парусном занятии).

Внешние системы (страховщики, погода, платежи, подпись, ИИ, антивирус, почта) — управляемые эмуляторы с тем же интерфейсом, что и будущие адаптеры. Никаких реальных платежей, полисов, ключей и публичного размещения.

## 2. Архитектура

Модульный монолит.

| Слой | Решение |
|---|---|
| Интерфейс и HTTP API | Next.js 15 (App Router), React 19, TypeScript, Tailwind CSS 4 |
| Данные | PostgreSQL 16, Prisma 6 (миграции, FK, уникальные и частичные индексы, транзакции, оптимистичные версии) |
| Валидация | Zod (строгие схемы: защита от массового присваивания) |
| Фоновые задачи | Отдельный процесс `worker` (tsx): таблица `Job` с `FOR UPDATE SKIP LOCKED`, повторы с задержкой, outbox → jobs, inbox вебхуков с уникальным внешним ключом |
| Время | `DemoClock` — смещение в таблице `Setting`, используется сервером и worker; ОС не трогаем |
| Авторизация | Собственные сессии в БД (случайный токен, в БД — SHA-256), Argon2id для паролей (`@node-rs/argon2`), TOTP (`otplib`) для сотрудников; cookie HttpOnly + SameSite=Lax + Secure при HTTPS; CSRF double-submit + проверка Origin; лимиты частоты в БД |
| Файлы | Приватное хранилище `storage/private` вне `public`, проверка сигнатур PDF/JPEG/PNG, карантин → демо-антивирус в worker, скачивание по короткоживущей HMAC-ссылке с проверкой прав |
| PDF | `pdf-lib` + шрифт DejaVu, водяной знак «Демонстрационный документ…», SHA-256 |
| Реальное время | Опрос раз в 4 с (`AutoRefresh`), сервер всегда отдаёт актуальный снимок |
| Тесты | Vitest (модульные и интеграционные против реальной БД `talisman_test`), Playwright (сквозные, 360 px и десктоп) |

### Модули (`src/server/*`)

`auth` (сессии, пароли, TOTP, CSRF, лимиты) · `access` (контекст организации, проверки прав) · `orgs` (агентства, проверки, полномочия, команда) · `catalog` (продукты, версии, тарифы, схемы анкет) · `requests` (заявки, версии, загрузки, распознавание) · `auction` (торги, предложения, сопоставимость, ранжирование) · `checkout` (резерв, документы, подпись, оплата, заключение) · `payments` (платежи, вебхуки, возвраты, сверка) · `commissions` · `subscriptions` · `events` (наблюдения, расчёт условий) · `claims` (обращения, выплаты, споры) · `messaging` (чат, уведомления, демопочта) · `ai` (распознавание, помощник с цитатами) · `automation` (правила автоответа) · `admin` (исключения, приостановки, двойное подтверждение) · `audit` · `jobs` · `adapters/*` (Carrier, Weather, Payment, Signature, Document, Messaging, AI, Antivirus — интерфейсы + эмуляторы).

### Машины состояний

Таблицы переходов в `src/server/state/machines.ts`: заявка, торги, предложение, оформление, договор, покрытие, проверка события, обращение, платёж, возврат, подписка, продукт, начисление. Любой переход идёт через `assertTransition()` — недопустимый отвергается сервером с кодом `INVALID_TRANSITION`.

### Ошибки API

`{ error: { code, message, nextAction, correlationId } }`. Коды: `FORBIDDEN`, `UNAUTHENTICATED`, `NEEDS_INFO`, `QUOTE_EXPIRED`, `VERSION_CHANGED`, `CAPACITY_EXHAUSTED`, `ALREADY_DONE`, `LIMIT_EXCEEDED`, `SOURCE_UNAVAILABLE`, `RESULT_PENDING`, `INVALID_TRANSITION`, `VALIDATION`, `CONFLICT`, `RATE_LIMITED`, `NOT_FOUND`, `INTEGRATION_NOT_CONFIGURED`.

### Идемпотентность

Таблица `IdempotencyRecord (userId, scope, key)` + хеш тела: тот же ключ и тело → сохранённый ответ; другое тело → `CONFLICT`. Вебхуки — `WebhookInbox(provider, externalEventId)` UNIQUE. Выплаты — `PayoutItem(eventCheckId, coverageCode)` UNIQUE. Начисления — UNIQUE `(policyId, recipientType, kind)`. Автоответ — `AutomationRun(ruleId, requestId, requestVersion)` UNIQUE. Использование лимита подписки — `ResponseUsage(orgId, requestId, periodStart)` UNIQUE.

## 3. Ключевые правила (демо-настройки)

* Торги: окно 5 мин; улучшение в последние 30 с продлевает на 30 с, суммарно ≤ 2 мин; шаг улучшения 100 ₽; агент видит только своё место и факт наличия лучшего предложения; публикация минимальной чужой цены — выключенная настройка.
* Одна активная версия предложения на (заявка, агентство, страховщик, продукт) — частичный UNIQUE-индекс.
* Цена предложения только в пределах тарифной сетки / котировки страховщика (`minPremium..maxPremium`); скидка из вознаграждения — отдельная строка с плательщиком.
* `coverage_fingerprint` = хеш нормализованных существенных условий (риски, лимиты, франшиза, территория, способ ремонта, срок). Разные отпечатки → разные группы сопоставимости.
* Резерв выбора 15 мин; один активный резерв на заявку (частичный UNIQUE); ёмкость страховщика — счётчики под блокировкой строки.
* Событийные продукты: покупка не позднее чем за 14 суток до начала; проверка двойного покрытия бронирования, совокупного лимита клиента и концентрации по ячейке/дате; проверка покрытия координат станцией.
* RAIN01: 59.9386, 30.3141; 19.06.2027 14:00–20:00 Europe/Moscow; DEMO_STATION_SPB_01 (резерв DEMO_STATION_SPB_02); ≥ 5.0 мм за 6 часовых интервалов; выплата 5 000 ₽; премия 500 ₽.
* WIND01: 20.06.2027 11:00–15:00 Europe/Moscow; DEMO_WIND_01 (резерв DEMO_WIND_02); < 3.0 м/с минимум в 3 из 4 часовых средних; выплата 3 000 ₽; премия 300 ₽.
* Величины хранятся целыми (сотые доли мм / м·с), деньги — целые копейки (`Int`/`BigInt`), без float.
* Комиссия: 15 % премии от страховщика (условно), 20 % платформе / 80 % агентству (10 000 ₽ → 300 / 1 200 ₽). Сторно: полное при прекращении в первые 14 дней, иначе пропорционально.
* Подписки: Старт 1 990 ₽ / 50 ответов; Про 5 990 ₽ / 300 + автоответ; Команда 14 990 ₽ / 5 пользователей / 2 000. Пробный период 14 дней, льготный период 7 дней, повтор оплаты по расписанию, смена плана со следующего периода.

## 4. Режимы

`APP_MODE=demo` (по умолчанию) — доступны демопанель, переключение ролей, эмуляторы. `APP_MODE=production` — демомаршруты отключены, эмуляторы запрещены; реальные операции требуют сконфигурированных адаптеров и записи о запуске (`LaunchApproval`) для сочетания страна/страховщик/продукт/канал/платёжный сценарий/версия документов. Иначе — `INTEGRATION_NOT_CONFIGURED`.

## 5. Порядок работ

0. Документы проекта, архитектура, модель данных.
1. Каркас, БД, миграции, авторизация, роли, загрузки, сиды, дизайн-система, изоляция.
2. Классическая заявка → торги → резерв → сделка → документы → подпись → оплата → полис → чат (сценарий А).
3. Событийный каталог, время и координаты, наблюдения, расчёт, обращение, демовыплата (сценарии Б, В).
4. Профиль агента, модерация продуктов, калькулятор, автоматизация, подписки, комиссии, сверка, отзывы, уведомления, продление (сценарии Г, Д).
5. Админ-исключения, негативные проверки, мобильная и доступная вёрстка, тесты, документация, блокеры P1, отчёт AC01–AC35.
